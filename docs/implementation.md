# 実装メモ

## 分担と構成

戦闘具・能力・ビルドUIを分担し、試合制御とライフサイクルを統合した後、別モデルで独立レビューしています。
共有APIは `api`、標準実装は `core` に置いています。

| 場所 | 役割 |
| --- | --- |
| `api/architect` | 式・相・術・具と能力イベントの契約 |
| `api/arena` | 試合、毎tickのCT、参加者の状態、参加前の復元 |
| `api/build` | ビルド制約、UUID単位の選択、永続化 |
| `api/util/Targets` | 視線・扇・球の命中判定。遮蔽物とワールドを確認 |
| `api/util/Combat` | ダメージ属性、再入時の文脈、所属と生存の確認 |
| `core/combat` | 具の設定読み込み、音・粒子、純粋な幾何計算 |
| `core/architect` | 標準34能力と短時間効果の実行補助 |
| `core/script` | JSONの19能力、Javaテンプレート・限定Lua・一括差し替え |
| `core/stage` / `core/game` | 既存ワールドの登録と単一試合・参加待機 |
| `core/stats` / `core/lobby` | 通算記録、ロビー・戦績・マップ・モードの画面 |
| `core/build` | Adventureを使うインベントリメニュー |

## 新しい能力を追加する

1. `BaseArchitect`（式なら `BasePark`、具なら `BaseTool`）を継承する。
2. `Skill` / `Passive` / `Park` / `Tool` を実装する。
3. `Architects.registerDefaults()` に登録する。
4. 調整値と表示名をリソースのYAML・翻訳へ加える。

相手や自分の状態を、共有インスタンスのフィールドへ保存しないでください。
`ArenaPlayer.state` は1回の生存期間、`matchState` は試合全体で保持されます。
不死の使用済みフラグと怨恨の再発動時刻は後者です。

繰り返し効果は `AbilitySupport.repeat` を使うと、退出・終了・能力解除・復帰で停止します。
対象を捕捉する場合は、対象の `getLifeGeneration()` も保存して毎回照合します。
具の表示エンティティや設置陣は `onUnequip` で即時除去してください。

## ダメージ処理

`Combat.damage` の属性は `TOOL` / `AREA_TOOL` / `SKILL` / `AREA_SKILL` / `SECONDARY`。
反響・鏡界の返しは `SECONDARY` を使い、反射や命中時の追加効果を再発動させません。
`Combat.damage` の戻り値は、命中して対象が同じ生存期間に残っている場合だけ `true` です。
鈍足・封殺・ノックバックなどの後段効果を付ける際に確認します。
撃破された対象はその場で復帰するため、無条件の後段処理は復帰先へ効果を与えてしまいます。

`onDamageDealt` と `onDamageTaken` は威力変更・防御用です。
ダメージ成立による効果は `onDamageConfirmed` / `onDamageTakenConfirmed` を使います。
これにより、能力の選択順に関係なく、護符や鏡で防いだ攻撃から追加効果が出ることを防ぎます。
他プラグインが御伽より後のイベント優先度でキャンセルした場合は、この確定通知の対象外です。

毎tick CTを進め、HUDは5tick、`Tickable` は20tick間隔です。
小数のCT倍率は端数を持ち越し、低倍率でも進行が止まらないようにしています。

## 現在の範囲

- 試合はFFA・残機戦・拠点制圧の3つ。明示的な参加待機から、1試合ずつ開始します。
- マップは運営が作ったロード済みワールドに範囲・spawn・観戦・復帰・拠点を設定します。ワールド・地形生成は行いません。
- 復帰は登録spawnから敵が最も離れた地点を優先します。残機切れは観戦地点へ移動します。
- サイドバーはモードに応じた順位と目標、ボスバーは時間や拠点の状況を示します。参加前のスコアボードを復元します。
- 設定再読込はYAML・翻訳・能力・マップ・モードを全て検証してから公開します。試合中は拒否します。
- 灯籠の照明は粒子と透明な敵の輪郭です。地形の光源は書き換えません。
- 残影は2秒間の防具立てです。標的を自動追尾する能力がないため、自動ロックの誘導機能はありません。
- 鏡界は前方防御として追従します。範囲攻撃では破砕され、反射は起きません。
- 帳の発光解除は本人が対象です。チーム概念の追加時に味方判定を差し替えます。
- 研澄の空振り判定は攻撃術の錨撃・断界が対象です。
- 既存の一部の式・相は数値をコード定数で持っています。追加能力・全具は設定から調整できます。

## 検証

JUnitでビルドの重複・式の併用・枠数、CTの端数進行と死亡時リセット、背面判定と異常値、吸収HPがある場合の致死判定、防御後の命中通知、復帰を跨ぐダメージの抑止を確認しています。
生のダメージイベントを組み立てる非推奨コンストラクタは、サーバーイベントを模すテスト内だけで使います。

Paper 26.2 build 134 の隔離したローカルサーバーで、プラグイン有効化、モード一覧、仮マップの不足項目表示、JSON/Lua検証、人数不足での開始拒否、正常停止を確認しています。
2026-10-19時点で自動テスト77件が成功しています。新モードの勝敗、戦績の永続化・重複防止、Luaの命令予算・状態分離・失敗後の後片付け、設定の検証と公開、蛇骨の蓄積と白兎の発動窓も対象です。玉手箱・件・一寸法師・修羅の条件と内部CT、鳴神・呼び声の予約解除、古い処理が次の生存状態へ持ち越されないことも検証しています。口裂けの追撃消費と期限、送り犬の被弾記録・内部CT・所有者分離も対象です。
隔離サーバー内に検証専用の小さな足場をコンソールから作り、既存ワールドの座標登録・安全性検証が成功することも確認しました。製品のマップ機能はブロックを変更しません。
能力の名前を変更してマップJSONを意図的に壊し、再読込失敗時に旧能力が残ること、修正後に新しい値を公開することも確認しました。
生成物は `build/libs/Otogi-0.1.0-all.jar`、自動テスト結果は `build/reports/tests/test/index.html`、起動・コマンド確認ログは `build/smoke/verified-v2.log` です。

導入前の対人確認では、次を確かめてください。

1. 選んだビルドが再接続後も残り、試合中は変更できない。
2. 刀・細剣・長柄の間合い、輪刃の行き帰り、書の陣が見た目と一致する。
3. 護符・鏡界・反響を組み合わせても追加効果が増殖しない。
4. 封殺中の発動拒否、浄化、怨恨のジャミング耐性が分かる。
5. 試合終了・途中退出で、持ち物や効果が元に戻る。

サーバー起動とコマンドの確認だけでは、対人での駆け引きや音量バランスは評価できません。
