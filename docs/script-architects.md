# JARを入れ替えずに能力を調整する

JSONは能力の名前・分類・数値・アイコンを定義し、JavaテンプレートかLuaを選びます。
Luaは短い条件や効果の組み合わせに使い、命中判定・対象走査・描画はJava側が処理します。

## 新規追加の順序

1. `docs/game/draft/<分類>/<id>.md` に、モチーフ、操作、効果、数値、狙い、相互作用を書く。
2. 既存のJavaテンプレートで表現できるなら、JSONだけで定義する。
3. 条件や組み合わせを変えたい場合は、限定ゲームAPIを使う短いLuaを添える。
4. `/otogi architect validate` で構文・型・ID衝突・Luaの読み込みを確認する。
5. 試合終了後に `/otogi reload` で反映し、`/otogi architect info <id>` とビルド画面で確認する。

実際に編集する場所は `plugins/Otogi/architects/`。JSONを複製してidを変えると、新しい能力として追加されます。
同梱能力のIDは `nova`、`hasshaku` のように実装方式を含めない名前です。旧 `script_` ID・JSONは互換読み込みするため、そのまま更新できます。旧JSONの編集値を保ち、新名の同梱JSONを重複追加しません。手動で整理するときは同じ能力の新旧JSONを両方残さないでください。
全ファイルを検証してから登録し、失敗時は設定・能力を差し替えません。変更したファイルはそのまま残るので、エラー箇所を直して再実行できます。

## Javaテンプレート

`backend: java` の `pulse`（範囲攻撃）、`lance`（直線攻撃）、`dash`（短い移動）、`mend`（自己回復）を同梱しています。
術専用の `thunder`（固定射線の予告攻撃）、`frost_cone`（扇形と減速）、`oni_frenzy`（代償付きの期限付き強化）も使えます。射程・威力・予告時間・倍率はJSONで変更できます。
`dread_sphere` は視線の先へ球形の予告領域を置き、予告後に範囲ダメージと術封印を与えます。`hasshaku.json` が編集例です。
この範囲ならプラグインの再ビルドは不要です。例として、次は短いダッシュ術の定義です。

```json
{
  "id": "sample_dash",
  "name": "風送り",
  "description": ["視線方向へ短く踏み込む", "CT 6秒"],
  "kind": "skill",
  "material": "FEATHER",
  "cooldown": 120,
  "backend": "java",
  "handler": "dash",
  "parameters": {"speed": 1.2, "lift": 0.18}
}
```

分類は `park` が式（1つまで）、`passive` が相、`skill` が術、`tool` が具です。
時間はtick（20tick=1秒）、HPはハートの半分を1と数えます。

## Lua

`backend: lua` と `script: scripts/<name>.lua` を指定し、スクリプトからフックのテーブルを返します。
同梱の羽衣・血脈・返照が、常時補正・内部CT付き回復・被弾後の反撃の例です。
利用できるAPIと引数、フック一覧は [運営用編集ガイド](../src/main/resources/architects/README.md) に記載しています。このガイドも初回起動でデータフォルダーにコピーします。

LuaにはJava参照・OS・ファイル・ネットワーク・動的ロードを渡しません。
命令数、呼び出し深度、ゲームAPIの回数、状態の個数に上限があります。
実行時エラーは当該プレイヤーの当該能力を試合終了まで停止し、属性補正と状態を除去します。他のプレイヤーは継続できます。
実行済みのダメージは巻き戻しません。

全く新しい物理演算や大規模な継続処理はJava実装で追加し、その調整値をデータへ出してください。
