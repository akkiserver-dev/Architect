# 自作マップとゲームモードの設定

マップの地形とワールドは運営が用意します。Otogiはロード済みワールド上に対戦用の座標を登録して利用します。ワールド生成、地形生成、ブロックの設置・消去は行いません。初回起動時はマップ未登録です。

## ゲーム内で自作マップを登録する

`otogi.admin` を持つプレイヤーで、使用するワールドに入って設定します。各操作は `plugins/Otogi/maps/<id>.json` に即保存されます。ワールド名とUUIDも記録され、再起動時に同じロード済みワールドを参照します。試合中は設定変更できません。

1. `/otogi map create garden 幽世の庭` で仮定義を作成します。
2. プレイ範囲の対角二点で `/otogi map pos1 garden`、`/otogi map pos2 garden` を実行します。高さも含む直方体です。戦場の床より下と、ジャンプ・高台・観戦地点より十分上の高さを含めてください。
3. 安全な足場の上で `/otogi map spawn garden add` を2点以上登録します。現在地の向きも保存します。同時参加の定員はspawn点数です。`spawn garden list`、`spawn garden remove 2`、`spawn garden clear` で確認・修正できます。
4. `/otogi map spectator garden` で残機切れの観戦地点、`/otogi map recovery garden` で復帰用の地点を設定します。両方とも範囲内の安全な足場を指定します。
5. 拠点制圧を遊ぶ場合は `/otogi map point garden 5` で現在地を中心、半径5ブロック（直径10ブロック）として設定します。後で大きさだけ変える場合は `/otogi map radius garden 8` を実行します。中心は移動せず、半径だけ即保存されます。半径は1〜64ブロックです。`radius` はコンソールからも実行できます。FFAと残機戦だけなら、拠点の設定は省略できます。
6. `/otogi map validate garden` で未設定項目をまとめて確認します。設定が揃うと範囲と足場、頭上空間、危険ブロックを検査します。`info garden` では拠点の半径と直径も確認できます。
7. `/otogi map select garden` で次のマップに選びます。全員が `/otogi game join` またはロビーメニューで参加待機に入り、管理者が `/otogi game start ffa garden` で開始します。

足場検査は登録時と開始直前の地形を参照します。参加者の元のワールド・座標・所持品・ゲームモード等は試合終了・退出・中止時に復元します。範囲外への転落は通常の死亡として扱い、直近の攻撃者がいれば撃破を帰属させます。観戦者の範囲外移動は観戦地点へ戻します。

## JSONを直接編集する

`maps/map.json.example` は構造を示す非アクティブなサンプルです。座標は例示なので実際の地形に合わせます。`<id>.json` として保存し、JSON内の `id` をファイル名と一致させます。`world` は既存のワールド名、任意の `worldId` はUUIDです。UUIDがある場合は取り違えを防ぐためUUIDを優先し、同名の別ワールドへ自動接続しません。

`spawns` は位置の配列、`min` と `max` が境界、`spectator` が観戦、`recovery` が復帰、`controlPoint` と `controlRadius` が制圧拠点です。位置は `x,y,z,yaw,pitch` を持ち、向きの省略時は0です。仮定義では位置を省略できますが、試合開始には2点以上のspawn・境界・観戦・復帰が必要です。拠点制圧モードは拠点も必要です。

試合が終わった状態で `/otogi map reload` または `/otogi reload` を実行するとJSONを反映します。マップJSONに誤りがあれば従来のマップ定義を維持します。新マップの追加、範囲・spawn変更、ルールの数値調整にはJARの入れ替えは必要ありません。既存地形は編集されません。

## ゲームモードと数値設定

| モードID | 勝利条件 | 同点時 |
| --- | --- | --- |
| `ffa` | 規定撃破数に先着。死亡後は即復帰 | 時間切れは撃破数、次に少ない死亡数。それも同じなら引き分け |
| `last_stand` | 設定残機を使い切ると観戦へ。最後の生存者が勝利 | 時間切れは残機、次に撃破数。それも同じなら引き分け |
| `king_of_hill` | 拠点を単独制圧すると毎秒1点。設定点数先取 | 時間切れは拠点スコア。同点なら引き分け |

拠点は設定中心から水平半径以内・高さ差3ブロック以内です。複数人がいる間は加点を止め、パーティクルで拠点外周を示します。ボスバーに制圧状況と最高点、サイドバーに自分の得点・残機とモードに応じた順位を表示します。

`plugins/Otogi/modes.json` の既定値は次の通りです。

```json
{
  "lastStand": {"lives": 3, "matchSeconds": 600},
  "kingOfHill": {"targetPoints": 60, "matchSeconds": 600}
}
```

残機は1〜100、目標点数は1〜7200、制限時間は30〜7200秒です。`/otogi map reload` または `/otogi reload` で検証して読み込みます。不正な設定では以前の値を維持します。開始済みの試合は開始時の値を保持します。FFAの数値は引き続き `config.yml` の `ffa` で設定します。

コマンド操作は `/otogi game modes` で説明を確認し、`/otogi game mode last_stand` で次のモードを選択します。`/otogi game start <mode> [map]` は待機者のみを参加させます。`/otogi game leave` で待機取り消し・試合退出、管理者の `/otogi game stop` で試合を中止します。中止は戦績の勝敗として記録しません。
